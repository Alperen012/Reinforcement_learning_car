# Audit of the original project (v0.1, commit `a793398`)

The original project was ~1,200 lines: `src/envs/race_track_env.py` (the env),
`src/train_sb3.py` (PPO training), `src/evaluate.py` and `src/test_env.py`
(manual driving). This audit was done before the rewrite. Two bugs were fixed
on that code first (commits `b317956`, `eb54e5e`), then it was replaced.

| Area | Finding | Severity | Resolution in v0.2 |
|---|---|---|---|
| Normalisation | `VecNormalize(norm_obs=True)` statistics were never saved. `evaluate.py` and the training preview fed raw observations to a policy trained on normalised ones. | Bug | The env emits observations already scaled to [-1, 1]. No obs normalisation, nothing to save. |
| Physics mode | pymunk resets forces after every `space.step()`, so engine/drag forces acted on only 1 of 5 substeps. Velocity was in px/s but clipped with px/step limits, so the car was 30× too slow. | Bug | Physics engine removed. One kinematic bicycle model with a grip limit (`racing_gym/car.py`). |
| Reward | Progress = drop in distance to the next checkpoint, clipped to [-2, +10]. The asymmetric clip let an agent farm reward by rocking forward and back. A checkpoint radius of 80 px also let it cut corners. | Design flaw | Progress = signed arc length along the centreline, unclipped. A test proves rocking earns exactly the net distance. |
| Observation | Absolute x/y and heading/π (which jumps between +1 and −1 on the bottom straight). The policy can only memorise one track. | Design flaw | Egocentric observation: lidar, speed, wheel angle, sin/cos heading error, lateral offset, curvature ahead. |
| Determinism | `reset()` ignored the seed and always started at the same pose. The 5 eval episodes were identical, so their mean was one sample. | Weakness | Seeded start position (and track, for random tracks). Evaluation uses fixed seeds. |
| Track | One hard-coded rectangle drawn with pygame. | Limitation | Spline tracks, four presets, and seeded procedural tracks with overlap checks. |
| Laps | A lap counted at the last checkpoint, not at the line. | Minor | A lap = one full track length of net forward progress. |
| Algorithms | PPO only, hyper-parameters in argparse. | Limitation | PPO, A2C, SAC, TD3, DQN via one registry. Hyper-parameters in TOML. |
| Reproducibility | No record of the config, versions or seeds per run. | Weakness | Each run dir has the resolved `config.toml`, `run.json` (versions, seed, time) and CSV logs. |
| Visualisation | ~200 lines of "swarm preview" that drove random cars, unrelated to the policy. A `SysFont` was created every frame. | Weakness | Pygame renderer with a reward/observation panel. Browser playground. GIF and learning-curve commands. |
| Tests | None. | Gap | 43 tests (API compliance, reward properties, end-to-end training for every algorithm, Python ↔ browser parity). |
| Docs | The README claimed early stopping (not implemented) and showed contradictory deterministic results. | Gap | README numbers come from `docs/results.md`, which is generated by commands in the repo. |
| Licence | No licence file. | Open | Not changed. Choosing a licence is the owner's decision (see README). |

## What was kept

* The idea: a top-down car with lidar, trained with Stable-Baselines3.
* The original rounded-rectangle circuit, as the `oval` preset.
* Checkpoint-based progress evolved into continuous centreline progress.
* Live visual previews evolved into the playground's training-stage slider.
